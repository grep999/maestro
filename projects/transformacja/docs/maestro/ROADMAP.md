# Maestro roadmap — TRANSFORMACJA

## Purpose

Build a coherent, playable simulation of Poland's economic transformation beginning in 1990, using historical evidence as constraints and calibration inputs rather than as a predetermined narrative.

## Current baseline

Version 0.4.0 mechanics prototype; historical atlas 0.1.0. Current source includes a deterministic simulation kernel, browser interface, five company transaction events, GUS aggregates, IMF 1990–September 1996 series, eleven research leads, regression tests and a provenance validator.

## Canonical cycle

GROUNDING → MOMENTUM → MASTERY → REPETITION → GROUNDING.

Architect, Researcher, Builder and Independent Reviewer are specialist capabilities. Momentum is not an agent; Repetition is not a worker. Copilot code review supplies an external review capability but does not replace a human release owner or Maestro's state machine.

## Next coherent increments

1. Complete repository integration and prove the imported candidate builds and tests from a clean checkout.
2. Complete independent review of the DCF/acquisition, ownership atlas and transaction casebook candidates.
3. Complete browser-driven interaction QA on desktop and mobile; headless Chromium previously timed out.
4. Improve finance with full cash-flow and balance-sheet consistency, explicit debt service, dividends, working capital and insolvency.
5. Expand the institutional model: privatization routes, tender rules, employee ownership, NIF governance, foreign-investment screening and regulatory conditions.
6. Expand the historical casebook only with source-backed events and transaction-level locators.
7. Calibrate macro and firm parameters from reproducible historical series; retain scenario ranges and uncertainty.
8. Add multi-region competition, supply chains, labour mobility, household distribution and political/institutional feedback.

## Mastery rules

A candidate is not accepted because code exists or tests pass. Require exact candidate identity, independent findings, reproducible checks, browser evidence, known limitations and explicit release authority. A BLOCKED or CONDITIONAL verdict must remain visible until resolved.
